\section{Introduction}

This project aims to predict the weekly occurrence of major crime types across Los Angeles using publicly available data from the Los Angeles Police Department. Predicting crime patterns is a valuable tool for law enforcement and city planners, as it supports proactive decision-making, effective resource allocation, and early detection of emerging hot spots [1]. The model developed in this work predicts whether a given crime type will occur in a particular region of the city during a specific week.

Our approach frames the problem as a multi-label binary classification task, where each label represents a different crime type. By incorporating short-term historical data through rolling temporal features, we enable the model to capture recent trends in crime dynamics. The focus is on establishing a clear and explainable baseline model that accurately captures temporal dependencies while serving as a foundation for more advanced methods.

Many existing works similarly tackle the task of crime prediction, albeit not necessarily with our identical approach or goal. For example, Ibrahim et al. (2024) combined convolutional neural networks with k‑means clustering to predict crime rates, outperforming traditional models [2]. Ladha and Patyal (2024) compared k‑nearest neighbours, SVM, and decision trees to classify regions into high, medium, or low crime [3]. Walczak (2021) used neural models with geospatial and temporal inputs to predict both crime type and location, aligning most closely with our task [4]. Obagbuwa and Abidoye (2021) applied linear regression to forecast urban crime incidents in South African cities [5]. Kshatri et al. (2021) applied a stacking‑ensemble SVM in India and achieved very high accuracy, showing that combining models can improve predictions [6].

Overall, many studies have advanced crime forecasting most commonly through deep learning. None adopt a unit of analysis as proposed in this project, allowing our approach to attempt a new gap. However, insights from these studies, especially their emphasis on handling imbalance, preventing overfitting, and calibrating predictions, would guide updated modelling choices, discussed in our progress section.

\section{Dataset}

The raw dataset consisted of over 1 million individual crime reports, transcribed from the original paper records. Each report included a date, time of occurrence, location, crime code, victim age, and other logistical attributes. The original dataset \href{https://www.kaggle.com/datasets/cityofLA/crime-in-los-angeles}{may be found here}.

To create a dataset suitable for the intended model, however, several restructuring steps were necessary.

\subsection{Preprocessing}
\begin{enumerate}
    \item Normalizing all column names in the provided \texttt{.csv} file, including aligning capitalization and trimming spaces.
    \item Dropping rows missing a time, date, location, or crime description, since these were essential identifiers.
    \item Dropping rows with coordinates outside the latitude and longitude bounds around Los Angeles (LA) (including a buffer margin).
    \item Grouping similar, overly granular crimes into classes via semantic clustering. For instance, theft of different dollar amounts is recorded as separate categories, which may have utility in law settings, but is an arbitrary distinction for our purposes. As an update from our previous version, we used sentence embeddings and k-means clustering from pre-trained models to combine similar descriptions into the most common of their cluster.
\end{enumerate}

\subsection{Transformations}
\begin{enumerate}
    \item Spatial aggregation: The LA area (including a buffer margin) was divided into 2 km$^2$ grid cells, with each cell treated as a single ``spatial unit.''
    \item Temporal aggregation: Crimes were grouped by week number and year. For example, crimes occurring on Tuesday and Wednesday of the 3rd week of a year would belong to the same ``temporal unit.''
    \item Count aggregation: The combined spatial-temporal unit (grid cell $\times$ week) was used to count the number of crimes per type.
\end{enumerate}

After preprocessing and transformation, the final dataset consisted of grid cell-week units, each with counts for every crime type.

\section{Features and Inputs}

The input features for the model include the aforementioned spatial and temporal identifiers, as well as engineered inputs derived from the dataset.

\subsection{Augmentations}
\begin{itemize}
    \item Rolling averages: Per crime type, the rolling average over the previous two weeks within the same grid cell was calculated. \textit{Rationale:} Crime can exhibit short-term "inertia", where activity in recent weeks influences upcoming activity [7]. Including rolling averages as a new feature helps the model capture these temporal dependencies more effectively than raw counts alone.
    \item Neighbour activity scores: A distance-weighted score summarizing crime activity in surrounding grid cells, computed using a 5\,$\times$\,5 spatial window. \textit{Rationale:} Crime can exhibit spatial "spillover", meaning events in one area can influence nearby areas [8]. Aggregating nearby activity encodes this spatial correlation directly into the model.
    \item Temporal effects: Week-of-year encodings and holiday-related features were added using simple Python utilities and manual calculations. \textit{Rationale:} Crime types can vary seasonally (e.g., holidays, weather patterns, academic calendars). Encoding seasonal and calendar-driven effects helps the model learn these periodic fluctuations.
\end{itemize}

Each input is represented as a single feature vector per unit, with multiple outputs corresponding to the counts of each crime type, allowing the model to predict multiple targets simultaneously.

Feature sets were varied systematically across averages. As a baseline, only the raw weekly crime counts were provided. Next, the raw counts combined with the temporal features were tested. Next, the raw counts combined with the spatial features were tested. Finally, a complete model considering all features was tested. This allowed observation of how each feature "category" impacted predictive performance. Based on experimentation, inclusion of all features yielded the best results, which may be attributed to data quality and relative sparseness of crime.

No representation learning methods were used; all features were manually engineered to maintain full interpretability.

\section{Implementation}

This section describes all models implemented for the project, including a simple baseline, the original logistic regression model, and the final improved model. 

\subsection{Majority Class Baseline}

The simplest baseline was a \textbf{per-label majority class predictor}. For each crime category, the training set proportion of positive labels was computed, and the baseline predicted the majority class for all test samples. Formally, for each binary label $y \in \{0,1\}$:

\[
\hat{y} =
\begin{cases}
1, & \text{if } \frac{1}{N}\sum_{i=1}^N y_i > 0.5, \\
0, & \text{otherwise}.
\end{cases}
\]

No parameters are learned and no features are used; predictions are determined entirely by label frequency.  
This baseline is important due to the extreme sparsity of crime occurrences—several crime types appear in fewer than 5\% of weeks, meaning an ``always zero'' model can achieve deceptively high accuracy.  
The baseline also preserves the same multi-label output structure as the trained models, enabling direct comparison.

\subsection{Original Logistic Regression Model}

The initial trained model used a \textbf{multi-label logistic regression} approach, training one binary classifier per crime category. Predictions were generated using:
\[
\hat{y} = \sigma(\mathbf{w}^\top \mathbf{x} + b),
\qquad 
\sigma(z) = \frac{1}{1 + e^{-z}}.
\]

\paragraph{Feature Set.}
The original model used only two-week rolling crime averages as predictors.

\paragraph{Loss Function.}
Each classifier minimized binary cross-entropy:
\[
\mathcal{L} = -\frac{1}{N}\sum_{i=1}^N 
\left[ y_i \log(\hat{y}_i) + (1-y_i)\log(1-\hat{y}_i) \right]
\]

\paragraph{Optimization.}
Batch gradient descent with a fixed learning rate was used.  
Labels with zero variance (all zeros or all ones) were skipped and predicted as constants during testing.

While this model established a baseline, it struggled with severe class imbalance and lacked mechanisms to prevent overfitting in higher-frequency categories.

\subsection{Improved Logistic Regression Model With Regularization and Imbalance Correction}

The final model extends the original logistic regression setup but introduces several key enhancements that match the implemented code.

\paragraph{Expanded Feature Construction.}
The updated feature set, constructed in \texttt{splitData()}, includes:
\begin{itemize}
    \item Two-week rolling crime averages
    \item Raw crime counts for each top crime type
    \item Neighbourhood activity score
    \item Holiday indicator
    \item Week number
    \item One-hot encoded season variables (dropping the first category)
    \item All remaining numeric features not excluded as identifiers
\end{itemize}

\paragraph{L1 and L2 Regularization.}
The loss function was augmented with both L1 and L2 penalties:
\[
\mathcal{L}_{\mathrm{reg}}
= \mathcal{L}_{\mathrm{BCE}}
+ \lambda_1 \sum_{j=1}^{d} |w_j|
+ \lambda_2 \sum_{j=1}^{d} w_j^{2}
\]

L1 encourages sparsity and implicit feature selection, while L2 stabilizes weight updates and reduces variance.

\paragraph{Class-Weighted Loss.}
To correct for imbalance, positive samples were weighted by:
\[
w_{\mathrm{pos}} = \frac{N_{\mathrm{neg}}}{N_{\mathrm{pos}}}
\]

This adjusts the gradients so that rare crimes influence the optimization more strongly.

\paragraph{Numerically Stable Sigmoid and BCE.}
The implementation includes:
\begin{itemize}
    \item An overflow-safe sigmoid function
    \item BCE loss with clipping to avoid $\log(0)$
\end{itemize}

\paragraph{Threshold Calibration.}
Instead of a fixed threshold of 0.5, the decision threshold for each crime label was set to:
\[
\theta = \max(0.05,\; \mathbb{E}[y])
\]
where $\mathbb{E}[y]$ is the empirical prevalence in the training data.  
This improves recall for low-frequency crimes while avoiding extremely small thresholds.

\paragraph{Multi-Label Training Loop.}
A separate logistic regression model is trained for each crime category.  
Labels with no positive cases are skipped and predicted as constants.  
For each label, the model outputs:
\begin{itemize}
    \item Learned weights and bias
    \item Calibrated binary predictions on the test set
    \item Per-label accuracy
\end{itemize}

\subsection{Model Comparison}

The improved logistic regression model outperformed the original model across most crime categories, especially for low-frequency crimes. Key findings include:

\begin{itemize}
    \item L1/L2 regularization reduced overfitting and improved generalization
    \item Class weighting prevented prediction collapse into the majority class
    \item Threshold calibration significantly improved recall in rare crime categories
    \item Expanded feature sets provided additional temporal and contextual signal
\end{itemize}

For labels with extremely low prevalence, the majority baseline performed competitively, illustrating that accuracy alone is insufficient for evaluating highly imbalanced datasets. Metrics such as recall and F1-score are necessary to assess true performance.

\section{Evaluation}

% Identify evaluation metrics and justify them.

To evaluate our models, we divided the processed dataset into training, validation, and testing splits based on temporal ordering. Because crime patterns evolve over time, we used a chronological split rather than random shuffling to avoid information leakage. Specifically, data from 2010--2015 was used for training, 2016 for validation, and the first half of 2017 for testing. This ensured that all models were evaluated on future crime patterns rather than past ones.

\subsection{Label Distributions and Class Imbalance}

Crime types exhibit extreme imbalance, with many labels occurring in fewer than 5\% of spatio-temporal units. This imbalance strongly influenced both model behavior and choice of evaluation metrics. Accuracy alone is misleading under such conditions because predicting ``no crime'' yields high accuracy for most labels. Therefore, we rely on:\\
\begin{itemize}
    \item \textbf{Precision} — how often predicted crimes were correct.
    \item \textbf{Recall} — how often true crimes were successfully detected.
    \item \textbf{F1 score} — harmonic mean of precision and recall, balancing the two.
    \item \textbf{Per-label accuracy} — included for completeness, but interpreted cautiously.
\end{itemize}

These metrics were computed independently for each of the 20 crime categories, producing a detailed per-class performance profile.

\subsection{Evaluation Procedure}

For each model variant (majority baseline, original logistic regression, improved logistic regression), predictions were generated on the held-out test set. We computed all classification metrics per label and averaged them to obtain macro-level summaries. Confusion matrices were also constructed for every crime type to break down true positives, false positives, false negatives, and true negatives. This helped diagnose systematic patterns such as frequent under-prediction of high-volume crimes.

In accordance with the final project requirements \cite{FinalProjectInstructions}, the evaluation strategy also includes comparisons to earlier metrics from our progress report. The expanded feature sets and class-balancing modifications introduced after the progress milestone led to measurable improvements in recall and F1 for multiple low-frequency crimes. However, high-frequency crimes (e.g., burglary, petty theft) remained difficult to capture reliably.

\subsection{Hotspot Visualization Evaluation}

In addition to numeric metrics, we evaluated the model’s spatial behaviour by visualizing predicted crime hotspots for a representative week in the test set. Figure~\ref{fig:hotspots} shows predictions for Week 10 of 2016, where each grid cell is plotted over the Los Angeles neighborhood map and shaded according to the predicted number of crimes.

This visualization is interpreted as follows:
\begin{itemize}
    \item \textbf{Color scale:} Darker red indicates a higher predicted crime count for that grid cell; lighter colors represent low predicted activity; white corresponds to zero predicted crimes.
    \item \textbf{Spatial grounding:} The background polygons represent official LA neighborhoods, allowing the prediction map to be interpreted in a geographically meaningful way.
    \item \textbf{Concentration of hotspots:} Predicted activity is concentrated in South Los Angeles and the Wilmington--San Pedro corridor. These regions historically experience higher crime density, and the model successfully reproduces this broad pattern.
    \item \textbf{Lack of northern predictions:} Minimal predicted activity appears in central and northern LA. This reflects both the sparsity of crime in those regions and the model's conservative tendency, as identified in earlier quantitative evaluations.
\end{itemize}

Interpreting the map alongside the confusion matrices and F1-scores shows that while the model is capable of learning coarse spatial tendencies (e.g., identifying general high-crime regions), it struggles to produce fine-grained spatial variation and may underpredict activity in moderately dense areas. This reinforces the conclusion that although the model captures macro-spatial patterns, additional spatial features or hierarchical models would be necessary to generate more accurate neighborhood-level hotspot predictions.

\subsection{Adequacy of Metrics}

The metrics used in the progress report (primarily accuracy) were insufficient due to the class imbalance inherent in crime data. The final evaluation relies on recall and F1—which reveal meaningful deficiencies in detecting actual crime occurrence—and confusion matrices, which highlight systematic prediction biases. This expanded evaluation framework aligns with the final project guidelines and provides an accurate reflection of model performance.

\section{Progress}

In terms of data processing, our previous approach to grouping similar crimes was simplistic, using arbitrary literal word-by-word comparisons for merging. We refined this by using a pre-trained model to semantically group crime descriptions, which produces more meaningful clusters. This adjustment was not planned as part of the original progress report, but was necessary to improve the quality of the dataset and ensure similar crimes are treated consistently.

In terms of feature engineering, we largely followed the plan outlined in the progress report, but made adjustments based on empirical observations. We tested multiple versions of rolling averages for each crime type and found that long-term windows were ineffective due to crime sparsity. For spatial features, we experimented with several grid sizes and aggregation methods before determining that a distance-weighted neighbor activity score provided the best representation of local crime correlations. Therefore, while overarching feature ideas were added as intended, the specific implementations evolved as we discovered which approaches were most suitable for the data without over-complicating the model space.

A significant portion of our progress involved refining the modelling pipeline itself. Our initial logistic regression model was intentionally simple, using only rolling averages as features and lacking any regularization or class imbalance handling. As we progressed, it became clear that this approach was insufficient as the model frequently collapsed into predicting only the majority class, and several labels showed signs of overfitting due to the unrestricted weight magnitudes. These issues motivated the development of the updated \texttt{updatedModel.py}, which introduced L1/L2 regularization, expanded feature sets, explicit class weighting, and calibrated decision thresholds. This transition was not part of the original project plan, but it became necessary after observing the behaviour of the first model and realizing that a more robust, imbalance-aware framework was essential for meaningful multi-label crime prediction. We also developed a baseline model (as explained in the implementation section) that was based on a majority vote system, such that we could see how our regression performed against the initial baseline. This followed our plan from the progress report, as the goal was to update the model with better feature engineering and regularization so to see if the overall model performance improves.

\section{Error Analysis}

To analyze model errors, we performed per-label metric calculation, confusion matrices, co-occurrence error analysis, and inspection of high-error samples. A clear and consistent pattern observed is that rarer crimes with distinctive patterns tend to be predicted more reliably, while common crimes with variable patterns are much harder to capture.

\subsection{Per-label Metrics}
As outlined previously under evaluation, for each crime type, precision, recall, F1 score, and accuracy were calculated, demonstrating high variability across labels when plotted (Figure 1). Low precision (e.g., burglary) shows the model frequently predicts that label incorrectly; low recall means it  fails to detect real cases of that crime; low F1 reflects poor overall performance on that label. Crimes with more consistent patterns (e.g., stalking, discharge firearms) have mildly higher precision, recall, and F1 scores.

These metrics highlight an issue of class imbalance, which means measures of accuracy do not fully represent model quality. Potential improvements include more sophisticated class weighting, oversampling of underrepresented crimes, or the design of multi-stage models tailored to different crime frequencies.

\begin{figure}[h]
    \centering
    \includegraphics[width=\linewidth, keepaspectratio]{data/error_analysis/plots/evaluation_metrics.png}
    \caption{Evaluation metrics per class.}
\end{figure}

\subsection{Confusion Matrices}
The confusion matrices (Figure 2) show that the model predominantly predicts the absence of crimes. We see very high true negative rates across most labels, especially for rare crimes like stalking or child annoying. On the other hand, true positives are low or nearly zero for most classes, indicating the model rarely predicts that a crime occurs. False negatives are seen in the high-frequency crimes, such as burglary and petty theft, meaning the model misses actual occurrences. Some mid-frequency crimes, like burglary from vehicle or vehicle stolen, show a mix of false positives and true positives.

These matrices communicate the model is conservative, accurately detecting absence but failing to identify most actual crime events due to sparsity. Potential improvements include integrating additional contextual spatial features from secondary data sources, tuning thresholds on a per-class basis, and exploring temporal sequence models.

\begin{figure}[h]
    \centering
    \includegraphics[width=\linewidth, keepaspectratio]{data/error_analysis/plots/confusion_matrices.png}
    \caption{Confusion matrices per class.}
\end{figure}

\subsection{Co-occurrence Errors}
The co-occurrence matrix (Figure 3) shows how often pairs of crimes are mispredicted together in the same temporal-spatial unit. Noticeably high counts between frequent, related crimes (e.g., burglary, petty theft, simple assault) show that when the model fails, it will mispredict multiple common crimes simultaneously. Rare crimes (e.g., stalking) have low co-occurrence counts with other labels, which is in line with the model's tendency to predict absences. 

This matrix shows errors are not independent; the model will systematically mispredict multiple crimes during weeks of elevated occurrences. We can see this concept reflected in select high-error samples, where there are 20+ rows for which 15+ out of 20 classes are incorrectly predicted. Potential improvements include explicitly modeling inter-class correlations to reduce these systematic errors.

    \centering
    \includegraphics[width=\linewidth, keepaspectratio]{data/error_analysis/plots/cooccurrence_errors.png}
    \caption{Co-occurrence errors between classes.}
\end{figure}

\subsection{Conclusion}
The error analysis methods performed demonstrate the underlying difficulty of predicting crime at the very granular temporal-spatial level chosen for this project. Crime data shows extreme sparsity and high variability across labels, limiting reliable predictive power of standard models. This is exacerbated especially by common crimes. 

The temporal and spatial clustering of events also introduces complex dependencies that a single-stage model is unable to effectively learn. Addressing these challenges will require handling class imbalance, better capturing spatio-temporal patterns, and integrating contextual features, since crime occurrence data in and of itself is sparse and stochastic. One potential direction is investigating hybrid models: using simple regression baselines with neural network extensions for fine-grained dependencies applied only where signal exists.
